CoLearn · target architecture

A teacher-grounded learning loop, not an assignment evaluator.

CoLearn keeps a configurable tutor, learning context, conversation history, and concept progress connected. Automated evaluation remains an optional formative sidecar.

System shape

01 · Clients

Student and teacher browser

Server-rendered HTML, shared CSS, and targeted HTMX refreshes.

02 · Application

Student and teacher use cases

One read model and workflow powers both the dashboard and JSON API.

03 · Services

Tutor agent and response policy

Mode selection, grounding, tone, and bounded evidence signals.

04 · Adapters

Repositories and provider gateway

Deterministic memory adapters now; durable and provider adapters later.

Teacher context

Publish concepts, objectives, versioned material, and source provenance. Configure the allowed tutor behavior without rewriting the student UI.

Student learning loop

Start or resume a session, ask a question, choose a mode, receive a grounded turn, and see the next concept action.

Formative evidence

Persist turns and learning signals separately from final grades. Evaluation is explicit and optional.

Agent contract

LearningRequest
  learner · course · concept · session
  message · mode · objective
  materials · recent turns · progress

LearningResponse
  kind · body · source references
  evidence drafts · next action
  confidence delta · escalation flag

Domain mapping

  • LearningSession replaces the assignment as the primary student interaction.
  • LearningTurn preserves the conversation and selected tutor mode.
  • LearningMaterial carries teacher or external provenance.
  • ConceptProgress stores confidence, status, evidence count, and next action.
  • Evaluation stays in the legacy assessment path for now.

Versioned API

GET /api/v1/student/dashboard
Course, concept path, active session, recent turns, and learning context.
POST /api/v1/student/sessions
Start or resume a concept session.
POST /api/v1/student/sessions/{id}/turns
Persist a student message and return a grounded tutor turn.
POST /api/v1/student/sessions/{id}/understanding-checks
Optionally turn the latest explanation into formative evidence.
GET /api/v1/teacher/dashboard
Class concept confidence, evidence activity, and support queue.
POST /api/v1/teacher/materials
Publish teacher or labeled external learning material.
PUT /api/v1/teacher/courses/{id}/tutor-policy
Update allowed modes and source policy.
Security boundary: the current demo uses query/header roles and seeded IDs so the slice is easy to run. Production must derive identity from authentication, enforce course and session ownership, and add bounded source ingestion before external retrieval is enabled.
