# Backend SDLC Tracker — Co-Learning Learning Domain

Single tracker for the phased backend work. Kept brief; status per phase only.
Constraint: no new dependencies (`go get` unavailable); extend existing packages.

| Phase | Scope | Status | Notes |
|---|---|---|---|
| 1. Learning domain foundation | Domain entities (session, turn, evidence, understanding check, course/concept/objective/material, tutor policy), repository ports, in-memory adapters, tutor + understanding-check services, student/teacher usecases, controllers/routes, bootstrap wiring. Current UI and `/api/v1/*` verified against it. | ✅ Done | Docs: `docs/project-architecture.md`, `docs/api.md`. Legacy assessment slice untouched and secondary. |
| 2. Minimal durable persistence | `repository.LearningSnapshot` (versioned, provider-neutral), snapshot export/restore on the memory adapters, `adapter/persist.LearningStore` (atomic JSON write via temp+rename), after-change hook on the mutating usecases, boot-time load-or-seed, graceful-shutdown flush, `LEARNING_STORE_PATH` config (`off` to disable). No repository port or API/UI change. | ✅ Done | Round-trip, seed-replacement, and mutation-persistence unit tests in `src/adapter/persist`; restart smoke test verified restore. |
| 2a. Persistence & workflow hardening | Snapshot validated before atomic replacement; unsupported snapshot versions preserved and fail startup closed; corrupt current-version snapshots quarantined before explicit reseed; v1 backward compatibility for historical evidence with empty/missing turn refs; `bootstrap.NewApp` returns `(App, error)` so configured-store failures fail closed instead of running mutable-but-ephemeral. Learning workflows use a reference-counted keyed lock (start by student/course, turns/checks by session) so unrelated learners are not serialized across the provider seam; pre-mutation session/mode/course/concept validation; unmatched student turn is retained and reused only on an identical body+mode retry; policy-reconciled session mode. HTTP: exact root route, JSON `404`/`405`/role envelopes, strict bounded `application/json` decoding (media type, size limit, unknown fields, single value), stable `sources: []`. Docker Compose durable named volume at `/app/data` with non-root (UID/GID 10001) ownership init. | ✅ Done (this commit) | No repository ports changed except `LearningSessionRepository.FindActive` gaining a concept argument. Real AI/provider and UI work intentionally out of scope (Phases 3–4). Not yet run in this environment: `go build`/`go test`/`go vet` and `docker compose` — verify in CI or on a Go/Docker-capable host. |
| 3. Real tutor gateway integration | Replace stub `LearningAgentGateway` / `FormativeCheckGateway` behind the ports with a configurable provider adapter; keep validation layer (`service.TutorAgent`) as the contract gate. | ⏳ Planned | No usecase/controller change needed — ports already primary. |

## Acceptance checkpoints
- Every phase: `go test ./...` green; UI surfaces and `/api/v1/*` endpoints unchanged or extended without breaking contract.
- Persistence guarantees from Phase 2: crash-safe writes (atomic rename), version-guarded restore, seed fallback on missing/corrupt snapshot.
- Persistence guarantees from Phase 2a: candidate snapshot validated before replacement; unsupported versions never overwritten and fail startup closed; corrupt current-version snapshots quarantined (not silently discarded) before reseed; prior v1 snapshots remain loadable.
- `docs/project-problem-statement.md` is never modified.
